# UOJ CodeInsight

面向程序设计课程的代码理解测评平台。基于学生在 UOJ 中提交的代码生成简短问题，帮助教师了解学生能否解释自己的实现，并完成作答、评分、人工复核和成绩复盘。

CodeInsight 以独立服务接入 UOJ：只读导入 Contest、题面和有效提交，在自己的 PostgreSQL 中保存测评数据，不向 UOJ 写回成绩，也不执行学生源码。

## 适用场景

- 课后或实验课抽查：围绕学生实际提交中的局部机制提问。
- 课前准备：提前生成问题，检查或编辑后再开放作答。
- 课后复盘：教师确认评分、公布成绩，学生查看反馈并申请复核。

测评提供代码理解的辅助证据，不能单独证明代码由学生独立完成。模型生成的问题与评分仍需要教师判断。

## 主要功能

| 环节 | 能力 |
|---|---|
| 导入 | 按 Contest 导入题目与有效提交，可用文本名单限定抽查范围；创建时冻结快照 |
| 出题 | 根据本人代码生成中英文简答和单选，后台持久任务显示进度，支持终止、重试与部分开放 |
| 教师准备 | 预览、手动编辑，或为未开始学生重新生成整套问题／单道原题 |
| 学生作答 | 同屏阅读题面和代码，自由切题、保存草稿、标记回看或疑问，统一交卷与到时自动交卷 |
| 评分复核 | 单选和空答本地计分，非空简答由模型评分；学生明确异议进入教师复核 |
| 成绩反馈 | 教师主动公布，学生只读查看本人答案、参考答案和反馈，并可逐题申诉；支持 CSV 导出 |
| 设置 | 教师账号默认值与阅读偏好、测评等级和申诉规则，以及平台共用的模型与任务参数 |

题面和问题支持 Markdown、数学公式及代码块；代码显示行号。教师端和学生端适配桌面与窄窗口，主要作答控件和弹窗支持键盘操作。

## 一场测评如何进行

1. **导入与配置**：教师输入 Contest ID，确认参与范围、各原题的问题安排和个人作答时长。
2. **准备问题**：后台为每名学生的有效提交生成问题；教师检查后开放，只有整套问题就绪的学生可以开始。
3. **完成作答**：学生使用 UOJ 账号密码或备用测评码进入，查看本人代码并回答问题；个人倒计时从开始作答计算。
4. **评分与复核**：交卷后后台评分，教师处理疑问、评分错误和待复核事项。
5. **公布与复盘**：进入窗口结束、作答及评分完成、复核解决后，教师公布成绩；学生经原链接查看本人结果并申请复核。

### 题量与时间

当前新建测评采用 `lightweight_v1`。默认每道原题为一道简答加一道四选一；Contest 有三道及以上原题时，最大 `problem_id` 的原题默认仅简答。教师可调整每道原题是否包含单选。

例如三道原题均有有效提交，默认共 **5 问、10 分、20 分钟**。学生只回答自己有有效提交的原题；每问满分 2 分，初始时长按实际问题数 × 4 分钟，也可设置固定总时长。进入窗口与个人作答时限分别计算。

单选覆盖局部执行追踪、边界行为和局部修改，服务端在学生及全场范围均衡分配三类题型，生成后选项顺序固定。已有测评保留创建时的规则，重试或重新生成不重新分配题型。

### 评分与成绩

简答按整体理解评为 0／1／2 分，接受语义正确的日常表达；评分模型独立判断，不接收出题参考答案。学生标记“题目有疑问”会进入教师复核，提出异议不等于自动获得满分。技术失败保留为评分错误，不补造分数。

成绩默认不公开。公布后统一展示本人逐题结果、参考答案和正确选项；学生成绩概览显示原始分／实际满分与等级。等级使用本场冻结的原始分分界，教师可以设置；申诉期限也随新测评保存。

历史 `legacy` 测评保留顺序提交和原有评分方式，不自动转换为新协议。独立模型题目质量审核目前默认暂停，历史结论保留。

## 技术结构

```text
UOJ（MySQL 只读查询 + Judger 提交归档接口）
  │
  ▼
FastAPI 后端 ── PostgreSQL（快照、题目、草稿、任务、成绩、审计）
  │    │
  │    └── 模型服务（出题 / 简答评分）
  ▼
React + TypeScript 前端（Nginx 提供静态资源与 API 代理）
```

| 目录 | 内容 |
|---|---|
| `backend/app/api/` | 教师与学生接口、认证及权限 |
| `backend/app/integrations/uoj/` | UOJ 只读查询与提交归档读取 |
| `backend/app/services/` | 导入、出题、作答、评分、公布及设置 |
| `backend/app/prompts/` | 版本化 Prompt |
| `backend/alembic/` | 数据库增量迁移 |
| `backend/tests/` | 后端测试与合成数据验证 |
| `frontend/src/`、`frontend/tests/` | 页面、组件和前端测试 |
| `docker-compose.yml`、`ops/` | 服务编排与维护脚本模板 |

后端使用 Python 3.12、FastAPI、SQLAlchemy、Alembic；前端使用 React、TypeScript、Vite、KaTeX。出题与评分使用数据库持久队列、租约和执行 token，支持重启后接续任务，并隔离迟到结果。恢复过程中外部模型请求可能重复，不保证仅调用一次。

## 配置与开发验证

配置入口为 [环境变量示例](.env.example)、[后端配置](backend/app/config.py) 和 [Compose](docker-compose.yml)。本项目提供源码与维护模板，目前未提供经过独立环境验证的一键部署流程。

- 接入 UOJ 需要配置只读数据库连接及提交下载接口；账号密码登录还需匹配 UOJ 的认证配置。
- 离线开发使用 `LLM_PROVIDER=mock`。真实服务的地址与密钥保存在部署环境；教师设置页可分别选择出题和评分服务。
- Compose 会自动运行迁移，但依赖预先配置的外部网络 `uoj-quiz-net`；显式 `environment` 项会覆盖环境文件中的同名值。
- 平台保存的运行参数优先用于任务，不能用环境初始值推断当前模型或并发。切换服务或模型并保存时会发出小型可用性测试，可能产生费用；这不代表教学质量验收。

以下命令用于本地开发验证，需要 Python 3.12、Node.js 和项目声明版本的 pnpm；先创建并激活 Python 虚拟环境：

```sh
python -m pip install -r backend/requirements.txt
cd backend
python -m pytest -q
cd ../frontend
pnpm install --frozen-lockfile
pnpm run build
pnpm run test
```

浏览器交互检查另运行 `pnpm run test:interface`，需要 Chrome 与独立安装的 Playwright。PostgreSQL 并发专项需要专用合成测试库，普通测试默认跳过；具体要求见下方文档。真实模型回归与普通 mock 测试分开执行。

现有验证覆盖草稿冲突、交卷与恢复、评分协议、成绩权限、申诉及页面渲染。合成测试和小规模模型样本不能证明生产最大容量或长期教学效果。

## 数据边界与问题反馈

仓库提供源码、Prompt、配置示例和合成测试。真实学生信息、提交、作答、成绩、数据库备份、环境文件和密钥不应进入仓库或 Issue。向外部模型提交的题面、源码与作答应由部署者按其教学环境的数据要求管理。

反馈问题时请提供复现步骤、预期与实际行为、代码版本以及经过脱敏的错误信息；尽量用合成数据复现。模型质量问题需要同时说明题目所考查的局部机制与判断依据，避免公开真实学生材料。
