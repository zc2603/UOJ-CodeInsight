# UOJ CodeInsight

面向程序设计课程的代码理解测评平台。独立部署，从 UOJ 导入题目与有效提交，在课前为每位学生预生成双语问题，教师确认就绪后开放测评。

## 功能

评分使用 grader_v8：按题目明确要求独立判断，支持部分分和坏题异议。每问返回0/1/2建议分；无法可靠判分时仍保留建议分与不确定性，交教师复核。有可靠评价单元时由程序计算分数；待复核建议分不计最终成绩。技术调用失败不伪造分数。出题继续使用 question_generator_v10。

- 每道有效题目生成两个问题，教师端显示出题及学生就绪进度。
- 持久化出题队列、跨进程并发上限、租约续期和失败重试。
- 教师可终止出题并保留完成结果，手动重试失败或已终止的题目。
- 已终止或部分失败的测评可经二次确认后开放，仅整套问题已就绪的学生可参加。
- 学生开始时加载已保存问题，按每问三分钟独立计时。
- 教师可预览未开始学生的问题、查看作答、复核成绩及导出结果。
- 支持重置、重新评分和经确认后删除测评。
- UOJ 集成仅执行读取操作，测评数据保存在独立 PostgreSQL 中。

## 开发

后端使用 Python 3.12、FastAPI、SQLAlchemy 和 Alembic；前端使用 React、TypeScript 和 Vite。

```sh
python -m venv .venv
# 激活虚拟环境后
pip install -r backend/requirements.txt
cd backend
python -m pytest -q
```

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm run build
```

本地配置可参考 `.env.example`，仅包含占位值。开发时使用 `LLM_PROVIDER=mock`；真实模型调用前必须确认范围与费用。

## 部署

Compose 依次启动 PostgreSQL、执行数据库迁移并启动服务。请先创建独立的 `uoj-quiz-net` 网络，并配置环境变量。默认端口为 8090，教师入口为 `/admin`。生产环境应配置 HTTPS。

`ops/` 提供白名单维护脚本模板：默认项目路径 `/opt/uoj-codeinsight`，示例维护账号 `quizmaintainer`。安装前由管理员按实际部署审查调整；不要直接覆盖现有服务器配置。离线 Dockerfile 还需要预备依赖与前端 dist；常规开发可使用标准 Dockerfile。

数据库迁移或批量数据操作前先备份。当前出题队列支持重启恢复；评分仍使用进程内后台任务，重启后中断的评分需要教师复核并重新评分。

## 数据与仓库范围

本仓库只包含程序源码、Prompt 模板、配置示例和人工构造的测试样例。测试代码中的源码片段、学号样式标识和固定问题均为合成夹具，不是生产学生记录。

不提交真实学生信息、提交源码、生成问题、作答或成绩，也不提交数据库、导出文件、运行日志、模型回归输出、环境文件或密钥。生产维护交接、内部部署地址和历史回归报告留在本地。

本仓库以审查后的当前版本建立全新提交历史，旧的本地维护历史不在上传范围内。后续功能使用独立分支，提交前检查 staged diff 并运行相关测试。服务器部署应记录对应提交哈希。


## 终止出题与部分开放

在课前准备卡点击“终止出题”，确认后停止等待中及正在生成的任务。已完成问题保留，终止状态不会因服务重启而恢复；已发出的模型请求仍可能计费。需要继续时，点击“重试未完成题目”。

已终止或部分失败的测评，至少有一名学生的问题全部就绪后可开放。确认弹窗列出可参加与暂不能参加人数，确认后终止剩余任务并开始 30 分钟进入窗口。问题未全部就绪的学生暂不能参加，也不会在登录时触发补充生成。

相关离线验证包含运行中终止、旧响应隔离、终止后重试、发布确认及学生进入限制；使用合成数据和 Mock 模型。
