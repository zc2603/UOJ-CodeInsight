# UOJ CodeInsight

面向程序设计课程的代码理解测评平台。平台只读导入 UOJ Contest、题目和有效提交，在独立 PostgreSQL 中保存快照、预生成问题、学生作答与评分，不向 UOJ 写回数据。

## 测评协议

每场测评都会保存所用协议版本。程序用固定标记 `legacy` 表示旧版测评，继续按顺序作答；`lightweight_v1` 按 Contest `problem_id` 从小到大排列原题，可逐题设置是否出第二问，学生可自由切题，答案草稿会保存到数据库。三题及以上时，最大 `problem_id` 的题只生成一道 explanation 简答，其余原题默认各有一道简答和一道单选。学生只回答自己有有效提交的原题；教师无需确认题目顺序。

新协议一次交卷冻结全部最终答案，超时由持久评分队列收取已保存草稿。单选和空白题本地评分；非空简答调用版本化评分协议。教师可逐题人工复核并留下审计记录。成绩在结束、评分及复核完成后由教师主动公布；学生只读查看本人结果，并可逐题申诉。公布成绩统一包含参考答案与正确选项，已公布的历史结果也适用；未公布前不返回答案。教师成绩页提供统一宽度的概览、学生表格和申诉卡片，支持展开作答上下文、回复及逐题调整分数。

新建测评默认启用 `lightweight_v1`（`LIGHTWEIGHT_CREATION_ENABLED=true`）；独立质量审核仍暂停（`QUALITY_AUDIT_ENABLED=false`）。四组用于生成题目的合成测试数据和六个评分测试用例已通过真实模型测试并经人工检查。已有测评继续使用创建时保存的协议版本；迁移 `0007_lightweight_v1` 不会自动重生成旧题或公布已有成绩。

创建页面的测评内容与个人时长设置默认收起，点击“调整”展开；支持手动输入每问分钟或固定总时长，总时长不超过 180 分钟。准备页按当前轮次实际生成的问题数量统计，兼容一问与两问配置。列表查询也读取生成结果，接口测试覆盖最终响应中的问题计数。

### 界面与交互

教师端“设置”按账号持久保存进入窗口、个人时长、题型模板、等级分界、成绩表与阅读偏好。新测评每问初始 **4 分钟**（常规 5 问为 20 分钟），创建时冻结本场规则；历史测评保留原时长。新增配置集中在设置页，创建页和重新开放弹窗沿用原有界面。详见[教师设置](docs/teacher-settings.md)。迁移为 `0008_teacher_settings`。

学生与教师共用本场原始分等级，初始分界为 A+≥9、A≥7、B+≥5、B≥3、C≥1、D≥0，可修改后用于新测评。教师测评列表与结果概览显示有效原始分均值；零分计入均值，未完成或待复核成绩不计入。

学生与教师页面统一使用墨绿色视觉风格，并适配桌面和窄窗口。学生结果页区分等待公布与成绩复盘，逐题展示本人答案、参考答案、评分反馈及申诉；新版作答页使用分组题号导航、整行单选和支持键盘操作的统一交卷弹窗。教师列表、创建和详情页面同步调整。普通 HTTP 下开始作答的白屏问题已修复。Chrome 合成浏览器检查覆盖 1366×768、900×768、390×844，以及登录、作答、交卷重试、成绩和申诉。验证范围与运行方式见 [界面验证说明](docs/interface-design-checks.md)。

## 开发验证

保存平台参数时切换服务或模型，会自动进行一次“1 + 1”JSON 问答检查，无二次费用确认。每个变化服务一次、每次保存最多两次 HTTP，单次至多 20 秒/2048 token，无自动重试；只改运行限制不触发。结果绑定保存版本，失败保留配置并显示原因。迁移 `0010_model_switch_tests`，旧记录不补发测试。

第二阶段设置增加新测评申诉期限/提示语，以及平台共用的模型服务和任务运行参数。DeepSeek 初始 `deepseek-flash`，可选 `deepseek-pro`；OpenAI API 初始 `gpt-5.6-sol`，另可选 `gpt-6-astra`、`gpt-6.1-sol`（已由用户确认可正常使用）。OpenAI 推理强度按原值发送，`max` 对应 `max`。出题与评分分别选择服务，后台每 3 秒加载新参数，运行中任务保留原快照；设置页显示进程加载状态。凭据保存在部署环境，页面和数据库配置不包含 API Key。详见[运行参数与申诉规则](docs/runtime-settings.md)。迁移 `0009_runtime_and_appeals`。

2026-09-29 修复未开始学生详情接口对新版 Prompt v2 的识别，保留 v1 和旧版测评兼容；后端全套 195 项测试通过，包含新版详情的题目数量、单选答案和只读检查。

后端使用 Python 3.12、FastAPI、SQLAlchemy、Alembic 和 PostgreSQL；前端使用 React、TypeScript、Vite。Mock 测试不调用真实模型。

```sh
python -m venv .venv
# 安装 backend/requirements.txt 后

python -m pytest -q

```

当前后端离线测试 269 项通过，新增覆盖超过三道原题时的题序、单原题重新生成、非法选项编辑返回 422、草稿清空与服务端恢复、重评不改完成时间、只读结果凭证不能写作答、评分协议不匹配与复核事项去重、逐题分与整份覆盖的互斥，以及最新迁移的增量与重复执行安全。独立 PostgreSQL 专项验证空库升级、`0009→0010` 保留旧审计记录及测试晚返回与新配置保存的隔离；前端构建和三尺寸合成浏览器检查通过。一次获准的隔离真实合成保存调用 OpenAI API 的 `gpt-5.6-sol`，简单问答通过（1 次 HTTP，约 1.9 秒）。此前验证还覆盖教师设置、运行参数加载、HTTP 作答、Markdown 安全、草稿、交卷、任务接管和申诉并发。这些测试不能说明线上最大负载或模型长期教学质量。

前期三轮探索测试共发出 14 次 HTTP；当时遇到的问题和费用估算保留在本地记录。补齐评分 Prompt 的格式要求并获批后，10 项固定测试全部通过：四组出题数据和六个评分用例均符合预期，并经人工检查。最后补测的五个评分用例发出 5 次 HTTP，模型返回用量为输入 3388 / 输出 1519 token，按官方 [DeepSeek API 高峰价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 估算 ¥0.018928；该次授权上限为 25 次 HTTP、并发 1、每个用例最多 5 次、每次最多 100000 token、预算 ¥22。最大 `problem_id` 的第三题只生成一道 explanation；第四个修改题仅为辅助样本，不对应实际题号。生成 Prompt v2 明确区分认知类型 `type` 与作答形式 `response_format`，并兼容 v1/v2 任务。真实模型测试程序每次发送 HTTP 请求前都会记录请求次数和费用预留；非 2xx 响应只保存脱敏、限长的 `type`、`code`、`message`，不保存错误原文。模型原始回答、题目文本、报告、防止重复运行的标记文件和内部验证材料均只保存在本地，不纳入仓库。

## 部署与数据边界

Compose 依次启动 PostgreSQL、迁移服务、后端与前端。涉及迁移时先备份数据库；前端离线镜像需包含本地构建的 `frontend/dist`。部署后核验健康、配置、迁移版本与资源哈希。维护脚本只是模板，安装副本须由管理员按环境审查。

仓库仅包含源码、Prompt、配置示例和合成测试。不得提交真实学生信息、代码、作答、成绩、数据库、运行日志、环境文件或密钥。如需再次进行真实模型测试，须先批准测试内容、包含重试的请求次数上限、并发数和费用上限。
