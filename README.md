## 教师端题目质量审核

新生成的每道原题两问保存后异步审核，逐问展示通过、明确不通过、无法确认和判定理由。审核不阻止题目就绪、开放或学生作答，不改成绩、不自动重出。明确不通过、无法确认、审核调用失败进入“需关注”；教师可逐问标记已查看，保留结论。

历史预生成题目默认为未审核，可在教师详情主动申请；失败可手动重试，操作会提示模型费用。历史即时出题的旧记录没有预生成任务，不自动补建审核。新题轮次独立，旧结论不覆盖新题。

审核使用 question_quality_v6 与当前配置模型，独立客户端每进程一个执行器（当前总并发 4），每组正常一次 HTTP 请求，1200 秒总时限、100000 输出 tokens。技术失败不自动重试；进程中断按租约恢复，最多领取两次，仍异常则提示失败。额外调用增加费用和资源占用，但不占出题/评分的请求信号量。判断尚未经过真实模型效果评估。

学生评分置信度 **≤ 0.85** 转教师复核；质量审核不再使用置信度。新评分和重新评分使用新阈值，不批量改变历史成绩。

# UOJ CodeInsight

面向程序设计课程的代码理解测评平台。独立部署，从 UOJ 导入题目与有效提交，在课前为每位学生预生成双语问题，教师确认就绪后开放测评。

## 功能

评分使用 grader_v8：按题目明确要求独立判断，支持部分分和坏题异议。每问返回0/1/2建议分；无法可靠判分时仍保留建议分与不确定性，交教师复核。有可靠评价单元时由程序计算分数；待复核建议分不计最终成绩。技术调用失败不伪造分数。出题使用 question_generator_v16，生成双语题干、中文参考答案和简洁评分点。

- 每道有效题目生成两个问题，教师端显示出题及学生就绪进度。
- 持久化出题队列、跨进程并发上限、租约续期和失败重试。
- 教师可终止出题并保留完成结果，手动重试失败或已终止的题目。
- 已终止或部分失败的测评可经二次确认后开放，仅整套问题已就绪的学生可参加。
- 学生开始时加载已保存问题，按每问三分钟独立计时。
- 教师可预览未开始学生的问题、查看作答、复核成绩及导出结果。
- 支持重置、重新评分和经确认后删除测评。
- UOJ 集成仅执行读取操作，测评数据保存在独立 PostgreSQL 中。

## 部署

Compose 依次启动 PostgreSQL、执行数据库迁移并启动服务。请先创建独立的 `uoj-quiz-net` 网络，并配置环境变量。默认端口为 8090，教师入口为 `/admin`。生产环境应配置 HTTPS。

`ops/` 提供白名单维护脚本模板：默认项目路径 `/opt/uoj-codeinsight`，示例维护账号 `quizmaintainer`。安装前由管理员按实际部署审查调整；不要直接覆盖现有服务器配置。离线 Dockerfile 还需要预备依赖与前端 dist；常规开发可使用标准 Dockerfile。

数据库迁移或批量数据操作前先备份。当前出题队列支持重启恢复；评分仍使用进程内后台任务，重启后中断的评分需要教师复核并重新评分。

## 数据与仓库范围

本仓库只包含程序源码、Prompt 模板、配置示例和人工构造的测试样例。测试代码中的源码片段、学号样式标识和固定问题均为合成夹具，不是生产学生记录。

不提交真实学生信息、提交源码、生成问题、作答或成绩，也不提交数据库、导出文件、运行日志、模型回归输出、环境文件或密钥。生产维护交接、内部部署地址和历史回归报告留在本地。

本仓库以审查后的当前版本建立全新提交历史，旧的本地维护历史不在上传范围内。后续功能使用独立分支，提交前检查 staged diff 并运行相关测试。服务器部署应记录对应提交哈希。


## 终止出题与部分开放

在课前准备卡点击“终止出题”，确认后停止等待中及正在生成的任务。已完成问题保留，终止状态不会因服务重启而恢复；已发出的模型请求仍可能计费。需要继续时，点击“重试未完成题目”。

已终止或部分失败的测评，至少有一名学生的问题全部就绪后可开放。确认弹窗列出可参加与暂不能参加人数，确认后终止剩余任务并开始 30 分钟进入窗口。问题未全部就绪的学生暂不能参加，也不会在登录时触发补充生成。

相关离线验证包含运行中终止、旧响应隔离、终止后重试、发布确认及学生进入限制；使用合成数据和 Mock 模型。


## 可选抽查名单

创建测评的第二步提供“参与范围”。不上传附件时为全部可参与学生出题；上传名单后，仅纳入名单与本场可参与学生的交集，其他学生不会进入该测评的参与列表或出题队列。

附件后缀不限，内容须为纯文本，最大 64 KB。推荐 UTF-8，每行一个学号（用户名），也支持空格、中英文逗号或分号分隔；不要添加姓名、标题、项目符号或序号。兼容带 BOM 的 UTF-16 文本，学号按完整字符串匹配，重复项自动合并。

页面显示实际入选人数、名单重复数，并可展开查看入选名单、不在本场学生列表及没有有效提交的学号。空名单、格式错误或零匹配不能创建。移除名单可恢复全员模式。创建时后台重新核对资格，按实际入选学生保存参与记录和有效提交，并建立出题任务。原始附件不落盘保存。

## 模型与并发

默认模型为 `deepseek-flash`，保留 thinking/max。默认4个服务进程，每进程20个出题循环，全局最多80个出题任务；每进程模型请求上限25（出题与评分共用），给评分留出容量余量，但不保证评分优先级。Compose 显式设置上述非敏感值，覆盖 env_file 中的旧值；调整时同步检查执行循环数和请求上限。

123项离线测试通过，包括模拟4个Provider的100个请求上限、排队与取消释放；没有真实API或PostgreSQL多进程压测。官方并发配额不等于应用容量，暂不直接升到250；需结合租约续期、数据库连接池、重试峰值和实际响应耗时继续评估。回退可将全局上限/每进程出题循环/请求上限恢复20/5/5后部署。

## 调用时限（2026-09-15）

请求超时为360秒（HTTP客户端超时，不是严格响应总时限）；后台出题每轮总时限1200秒，含排队和内部重试。输出上限100000 tokens，包含思考内容；请求超时和token上限由出题与评分共用。模型仍为deepseek-flash，出题全局并发80，重试次数不变。Compose显式覆盖上述三项值。125项离线测试通过，未执行新增付费模型测试。


## 重新开放已结束的测评

在测评列表的更多操作中选择“重新开放测评”，确认后最后进入时间更新为当前时间的 30 分钟后。进入窗口已结束但仍有人作答的测评也可重新开放。已有题目、作答、成绩和学生个人截止时间保持不变，不会重新出题，也不会让已提交学生自动重答。未参与学生仍须满足原测评的参与资格和整套问题就绪要求。重复请求不会继续延长开放窗口。


## 重新生成预生成题目

教师在未作答学生的预生成题目详情页点击“重新生成题目”，确认后为该学生的全部有效题目创建新一轮任务（产生模型费用）。旧生成记录保留，其他学生不受影响。新题全部完成前，该学生暂不能开始；完成后开始测评只使用最新轮次。该学生正在出题、已开始或已提交时拒绝重新生成。已重置的学生可以在当前轮出题结束后重新生成。


## 到时自动交卷

学生作答时自动保存当前问题的草稿，个人计时结束后显示“时间已到，已自动交卷”。后台独立收取已提交答案与截止前保存的草稿，未作答部分计零分并正常评分；关闭页面不影响超时处理。已有超时记录也会补入评分，旧版未保存的文字无法恢复。教师结果表以“超时自动交卷”标记来源，分数及复核规则与正常交卷一致。

超时评分使用持久状态和可续租任务，进程重启后可接续；模型错误进入评分异常，教师可重新评分。普通手动交卷的后台评分仍沿用原流程。


生成问题的中文题干和英文对照支持 Markdown 与公式渲染，包括代码块、列表及表格；学生作答页、教师预生成预览和作答详情采用相同显示方式。已有题目刷新后即可按新格式显示。


评分任务现已持久化：普通交卷、超时交卷和教师重评共用数据库队列。重启后租约过期的任务自动接续，迟到结果不能覆盖新执行器或已重置记录。每进程 4 个执行器，3 秒轮询、90 秒租约、15 秒续租，整轮上限 1200 秒。技术失败转评分异常，由教师重评；重评接口立即返回入队状态。恢复可能重复调用外部模型。复用迁移 0005 字段，无新增迁移。

出题与质量审核同步四类标准：解释题结合源码说明一个机制；追踪题优先少量步骤的局部状态；边界题聚焦一项合法边界处理；修改题明确局部目标与范围，只要求方案。审核检查代码关联和推演负担，仍只提示教师，不阻断测评。
