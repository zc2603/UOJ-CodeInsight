# 评分持久化与重启恢复

## 状态与事务

Attempt 本身是持久任务，不引入第二份任务表。最后一问的 Answer 与 GRADING 状态在同一事务提交，因此 HTTP 响应丢失或进程立即退出不会丢任务。超时交卷在领取事务内补齐草稿/空答案；普通 GRADING 缺少答案则转 GRADING_ERROR，避免伪造历史作答。教师重评以行锁入队，正在 GRADING 时返回已有任务，不重置租约。

## 执行与恢复

所有 API 进程启动固定数量执行器。PostgreSQL SELECT FOR UPDATE SKIP LOCKED 选择待评分或过期租约，生成新的 token 并提交后才调用模型。90 秒租约每 15 秒续租；没有租约的历史 GRADING 可立即领取。重启取消本地执行，保留数据库状态；租约失效后其他执行器接续。3 秒是空闲轮询间隔，队列积压时不保证 93 秒内开始。

成绩、日志及终态在持有 Attempt 行锁、确认 token 与 GRADING 状态后一起提交。旧执行器的成功/失败均不能覆盖新执行器或 RESET。重评保留人工分与已有待复核标记。任务完成后不再次自动领取。

整轮 1200 秒包含信号量排队与 Provider 内部重试。模型失败、整轮超时或执行异常进入 GRADING_ERROR，停止自动领取，教师可重评。取消时清理本地并行评分调用。数据库不可用时状态可能暂时无法更新，恢复连接后依靠原租约接续。

## 兼容与边界

复用 0005_timeout_submission 的 grading_token / grading_lease_until，无新增迁移。部署必须整体替换 API 和 worker；旧版无 token 的执行器不应与新版长期混跑。教师 regrade 返回入队状态而非完成成绩，前端提示已相应更新。

交付语义为至少一次执行、token 防止重复落库；外部模型请求在崩溃后可能重复并产生费用。无需引入 Redis/Celery。每进程 4 个评分执行器继续受既有共享 LLM 并发限制约束。

离线测试覆盖新会话领取、任务取消后租约接管、旧 token、Reset 后迟到成功/失败、重评重复点击、超时和不完整历史记录；SQLite 测试不等同于 PostgreSQL 多进程压力验证。没有发起额外真实模型测试。
