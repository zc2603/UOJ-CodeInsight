## 请求如何组成

- 出题：出题正文 + `llm_provider.py` 的本次 `KIND_RULES` + 原题、带行号源码及输出字段说明。每次只追加指定的第二问题型。
- 审核：审核正文 + 原题、带行号源码、两问及生成参考答案。独立请求，只给教师提示，不阻止开放、不自动重出或改分。
- 评分：评分正文 + 原题、带行号源码、问题和学生回答。Provider 不把生成参考答案、评分点或审核结论发给模型；程序将评价单元映射为分数。

## 统一定义

**作答要求**是题干明确要求交付的一个结果、一段围绕同一目标的解释或一项修改方案。一个要求可以需要多步推理；题干另行要求可分别作答、独立判对错的内容，属于附加任务。

**推理步骤**是完成回答所需的过程。参考答案涉及多处代码或补充推理，本身不增加题干的任务数量。

**评价单元**由评分模型依据题干要求确定，用于评价学生回答。评分仍覆盖实际题干的全部明确要求，兼容已有题目；一个序列整体评价。不能把评分单元数量直接当作题干任务数量。

**可判断的答案**指能依据题干和源码核验正确性。结果题的所问结果须可确定；修改题允许多种符合目标和限制的方案。

**审核 fail**表示设计违规或内容错误；**评分 invalid**专指影响作答的实质缺陷。两个结论用途不同，设计不合格不会自动触发坏题异议满分。

## 人工语义核对示例

以下为规则解释用的合成例子，不是模型实测结果；实际审核还须结合完整题面和源码。

| 场景 | 预期边界 |
|---|---|
| “解释这段倒序移动为什么能保留尚未搬移的元素。”回答需要说明读写顺序和覆盖关系 | 一个解释目标，可以多步推理 |
| “写出移动后的数组，并解释为什么要倒序移动。” | 结果与解释分别交付，属于多任务 |
| “在指定循环内修改代码，使数组元素按给定目标移动。”存在两种合法方案 | 多种正确方案不等于信息不足 |
| “给出修改方案，并证明修改后其他位置始终不变。” | 修改外附加证明任务 |
| 追踪题问最终输出，但必须理解源码中的特殊遍历顺序 | 不因最终输出形式本身判失败 |
| 题目含两个清楚且可回答的任务，学生指出“有两问” | 设计可以 fail；仅此不足以确认影响作答的实质缺陷并给异议满分 |
