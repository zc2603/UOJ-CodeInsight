# 申诉规则与模型/任务参数

所有新增配置入口均位于教师端“设置”。

## 申诉默认规则（教师账号级）

- **默认期限**：不限期，或公布成绩后 1–365 个整天；一天为连续 24 小时。
- **填写提示语**：1–500 字，去除首尾空白后不能为空。
- 新建测评保存规则快照，从首次公布时间计算截止时间。修改账号默认值不会缩短旧测评的申诉期；历史无快照的测评仍不限期。
- 学生成绩页原申请区域显示截止时间、关闭状态和本场提示语，服务端按实际请求时间校验。
- 期限结束后拒绝新申请，已成功提交的相同幂等请求仍返回原申请。待处理申请可继续由教师处理。
- 原有同题成绩版本限制、身份检查、只读结果登录及人工审计继续适用。

## 模型服务（平台共用）

| 服务 | 初始模型 | 可选模型 |
|---|---|---|
| DeepSeek API | `deepseek-flash` | `deepseek-flash`、`deepseek-pro` |
| 备用 OpenAI-compatible API | `gpt-5.6-sol` | `gpt-5.6-sol`、`gpt-6-astra`、`gpt-6.1-sol` |

出题和评分可以分别选择服务，使用该服务当前选定的模型；两者初始均使用 DeepSeek。切换由教师保存设置触发，不在错误时自动跨服务调用。`gpt-6.1-sol` 按要求保留，接入时未出现在提供方模型列表中；模型列表查询不代表付费生成/评分质量验证。

服务地址和凭据由部署环境提供。页面只展示地址、模型选项及凭据是否配置，不提供或返回 API Key。DeepSeek 使用 `LLM_BASE_URL` / `LLM_API_KEY`；备用接口使用 `OPENAI_BASE_URL` / `OPENAI_API_KEY`。

DeepSeek 保持 `thinking=enabled`，使用 `max_tokens` 和 `low/high/max` 推理强度。OpenAI-compatible 使用 `max_completion_tokens`，不发送 DeepSeek 的 `thinking` 扩展；`max` 映射为 `xhigh`。两者均保持 Chat Completions JSON 协议和已有有界重试；实际提供方兼容性需要另外批准真实调用验证。

## 可调整任务参数

| 参数 | 初始值 | 范围 |
|---|---:|---|
| 推理强度 | max | low / high / max |
| 输出 token 上限（含推理） | 100000 | 1000–100000 |
| 请求网络阶段超时 | 360 秒 | 10–1200 |
| 出题单轮总时限 | 1200 秒 | 30–3600 |
| 出题最大自动轮次 | 3 | 1–5 |
| 全局出题并发上限 | 80 | 1–100 |
| 评分整轮总时限 | 1200 秒 | 30–3600 |

初始运行参数以部署值为基础，以上为当前标准值。每进程请求并发和出题/评分执行器数量只读展示，调整执行器数量仍需部署。并发上限是领取任务的上界，不是吞吐保证。

各进程每 3 秒加载保存值并上报版本。设置页显示在线进程数和已加载进程数；无在线确认时明确提示。任务领取前绑定配置快照，运行中的任务、HTTP 重试、日志中的模型名称保持一致。切换服务或模型时，同一进程所有新旧任务客户端共用请求信号量；降低全局并发后已有任务正常完成。

平台参数保存要求有效教师身份、预期修订号，冲突返回 409；每次修改保存操作者、修订号和不含密钥的参数快照。`GET/PUT /api/admin/runtime-settings` 与账号级 `/api/admin/settings` 独立。

## 部署

- 迁移 `0009_runtime_and_appeals`：Quiz 增加申诉规则；新增平台运行配置、修改记录和进程加载状态表。迁移不回填旧申诉截止日期。
- Compose 在原环境文件之外，可选读取被 Git 忽略的 `.env.openai.local`，或 `OPENAI_ENV_FILE` 指定的文件（需支持可选 env_file 的 Compose 版本）。此文件可仅包含备用服务地址与密钥，应使用受限读取权限，独立于源码发布包管理。
- `config` 输出部署初始值和凭据是否配置；`smoke` 额外输出数据库保存的运行参数、版本和在线加载状态。
- 迁移后需要支持新配置的后端。排查切换问题时先看保存版本和进程回执，再查看对应任务记录中的模型；不要用环境初始值推断任务实际选型。
